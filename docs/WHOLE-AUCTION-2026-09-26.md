# 전량경매 설계 문서 구현 결과 (2026-09-26, 2026-09-29 정책 확정)

"덤핑몰(BidOn) — 전량경매 시스템 설계 문서"를 기존 사이트 위에 구현한 결과입니다. 기존 전량·부분 경매, 차순위 승계, 입금 확인, 정산 흐름은 그대로 두고 설계 문서의 규칙을 더했습니다.

- 상태: 2026-09-29 운영 반영 완료.
- 2026-09-29: 배포 전 정책 결정을 받아 반영했습니다(2절).
- DB: 새 컬럼·테이블 마이그레이션은 이미 Neon에 적용했습니다(추가 전용이라 현재 배포된 코드에 영향 없음).

## 1. 설계 문서 항목별 구현

| 설계 문서 | 구현 | 위치 |
|---|---|---|
| 즉시체결가 공개, 이상 입찰 시 즉시 낙찰 | 전량 경매 등록 시 선택 입력. 입찰가 ≥ 즉시체결가면 **서버의 한 SQL 문**이 경매를 닫고 즉시체결가로 주문을 만듭니다. 더 높게 불러도 즉시체결가로 낙찰됩니다. 동시에 두 명이 눌러도 주문은 1건 | `placeWholeBid()` in `lib/auction-core.ts` |
| 최저낙찰가 비공개 | 구매자 API 응답(마켓, 실시간, 내 입찰)에 최저가 금액·도달 여부·마감 사유가 없습니다. 공급자와 운영자만 봅니다 | `auctionView()` in `app/api/market/route.ts`, `app/api/auctions/[id]/live/route.ts` |
| 현재 최고가보다 높아야 입찰 | 기존 호가 단위 규칙 유지. 즉시체결가는 호가 단위와 무관하게 항상 유효한 입찰가 | `minimumBid()` |
| 실시간 가격 갱신 | 상세 화면이 3초마다 `/api/auctions/[id]/live`를 조회. 바뀐 게 없으면 304로 끝나 가볍습니다. 서버 시각으로 카운트다운 보정 | `useLiveAuction()` in `components/market/auction.tsx` |
| 즉시체결가 인상 자유, 인하는 현재가 아래로 불가 | 인상·삭제 자유. 인하는 현재 최고가보다 높고 최저낙찰가 이상일 때만. 인하하면 입찰자에게 알림. 입찰과 동시에 바꿔도 조건부 UPDATE라 어긋나지 않음 | `set_instant_price` 액션 |
| Case A: 최저가 이상이면 자동 낙찰 | 기존과 동일 | `closeWhole()` |
| Case B: 최저가 미달 | 확정 정책: 판매자가 24시간 안에 판매 여부를 정하고, 판매하면 최고 입찰가로 **바로 거래 성사**(구매자 재확인 없음). 거절·무응답은 유찰 | `closeWhole()`, `resolveBelowReserve()` |
| 입금 확인 후 연락처 공개 | 기존과 동일 | `markPaid()` |
| 에스크로 상태 흐름 | 입금 대기 → 입금 확인 중 → 연락처 공개(입금 확인) → 출고 → 거래 완료 → 정산. 입금은 플랫폼 계좌로 받아 정산 전까지 보관 | 주문 화면 |
| 검수 사진 | 출고할 때 공급자가 직접 올린 사진 1~5장이 **필수**. 구매자·운영자가 주문 화면과 분쟁 화면에서 봅니다 | `mark_shipped` 액션 |
| 구매자 수령 확인, 자동 승인 | 출고 후 7일 동안 수령 확인이나 신고가 없으면 자동 거래 완료 | `processAuctions()` |
| 수수료 3%, 판매자 부담 | 기본 수수료를 5%에서 **3%**로 변경. 카테고리별 요율은 기존대로 | `feeRateBps()` |
| 분쟁 테이블, 위약금 10% | `disputes` 테이블, 신고·소명·운영자 처리(기각/취소·환불/부분 환불), 책임 쪽에 거래대금 10% 위약금 | `lib/disputes.ts` |
| 자전거래 방지 | 사업자번호 체크섬 + 국세청 상태 조회(키 등록 시), 판매자와 같은 사업자번호 계정 입찰 차단, IP 해시 기록과 운영자 의심 목록, 운영자 경매 중단 | `lib/trust.ts`, 운영 탭 → 부정거래 |

## 2. 확정된 정책 (2026-09-29)

1. **최저가 미달: 판매자만 결정합니다.** 마감 때 최고 입찰가가 최저낙찰가보다 낮으면 판매자에게 24시간 안에 "그래도 이 가격에 팔지" 묻습니다. 판매하면 최고 입찰가로 바로 낙찰되고 구매자에게 입금 안내가 갑니다. 입찰 자체가 구매 의사이므로 구매자에게 다시 묻지 않습니다. 거절하거나 24시간 동안 답이 없으면 유찰입니다.
   - `BELOW_RESERVE_POLICY=buyer_only`(구매자에게 묻는 방식)는 코드에 남아 있지만 쓰지 않습니다.
2. **수수료는 판매자 3%, 구매자 수수료는 없습니다.** 운영 값은 `PLATFORM_FEE_RATE=0.03`입니다.
3. **미입금 자동 위약금은 끕니다.** 운영 값은 `PENALIZE_NONPAYMENT=false`입니다.
4. **입금 기한은 낙찰 후 24시간입니다.** 기한이 지나면 주문이 자동 취소되고 판매자와 구매자에게 알림이 갑니다. 판매자 알림에는 다시 경매할 수 있다는 안내가 붙습니다.
5. **차순위 승계는 하지 않습니다.** 미입금, 운영자 취소, 분쟁 취소 어느 경우에도 다음 입찰자에게 넘기지 않고 유찰로 끝납니다. 상품 등록 화면의 승계 체크박스도 숨겼습니다. 나중에 다시 켜려면 `AUCTION_SUCCESSION=on`.
6. **최저가 비공개와 출고 사진 필수는 그대로입니다.**
7. **국세청 조회는 키를 받은 뒤 등록합니다.** 번호의 영업 상태만 확인하며 소유자 확인은 아닙니다.
8. **분쟁 위약금(10%)은 유지합니다.** 운영자가 분쟁을 처리할 때 책임 쪽에 부과할 수 있습니다. 미납 위약금이 있으면 입찰·재고 등록·구매 수락이 막히고, 위약금이 생긴 뒤 같은 사업자번호를 등록한 계정에도 적용됩니다. 그보다 먼저 그 번호를 쓰던 계정은 막지 않습니다.
9. **이번 범위에서 제외**: PG 에스크로, 위약금 자동 징수, 대표자명 소유 확인. PG 에스크로는 상용화 단계에서 다시 논의합니다.

## 4. 동작 흐름

### 즉시체결가
- 등록: 전량 경매에서만. 최저낙찰가 이상, 정상가 이하.
- 입찰: 상세 화면의 "즉시구매" 버튼은 확인 창을 연 순간의 가격을 서버에 보냅니다. 그 사이 판매자가 가격을 바꾸면 확정 버튼이 막히고, 서버도 409로 거절합니다.
- 현재가 이상 입찰 폼에 즉시체결가 이상을 적어도 즉시체결가로 낙찰됩니다.
- 판매자 수정: 상세 화면 "즉시구매가 조정"(`set_instant_price`). 재등록 때도 새로 정할 수 있습니다.

### 최저가 미달
1. 마감 → 경매 `deciding`, 상품 `pending`(마켓에서 숨김). 공급자에게 "판매 결정 필요", 최고 입찰자에게 "판매자가 24시간 안에 정합니다, 판매하면 바로 낙찰" 알림. 다른 입찰자에게는 일반 마감처럼 보입니다.
2. 공급자 "이 가격에 판매" → 최고 입찰가로 바로 주문 생성(입금 대기 24시간), 구매자에게 낙찰·입금 안내.
3. 공급자 "판매 안 함" 또는 24시간 무응답 → 유찰. 다시 경매 가능.

### 미입금
- 낙찰 후 24시간 안에 입금이 확인되지 않으면 주문이 자동 취소되고, 판매자에게 "입금 기한 초과, 다시 경매할 수 있어요", 구매자에게 "주문 취소" 알림이 갑니다.
- 차순위 제안과 자동 위약금은 없습니다. 상품은 유찰 상태가 되어 판매자가 조건을 바꿔 다시 경매할 수 있습니다.

### 입금 확인 방식
- 구매자는 플랫폼 계좌(`PLATFORM_BANK_ACCOUNT`)로 계좌이체하고, 입금자명에 주문별 4자리 입금 코드를 적습니다. 가상계좌는 없습니다.
- 확인은 지금 **운영자 수동**입니다. 운영자가 통장 입금을 보고 운영 탭에서 "입금 확인"을 누르거나, "입금 관리"에 입금 내역을 입력해 주문과 연결합니다. 확인되면 양쪽 연락처가 공개됩니다.
- 자동 확인 경로도 준비되어 있습니다. 은행 입금 알림 문자를 전달하는 앱이나 은행·PG의 입금 통지를 `/api/webhooks/deposit`에 연결하면, 코드와 금액이 맞는 입금은 자동 확인됩니다. 인증 비밀값(`DEPOSIT_WEBHOOK_SECRET`)은 등록되어 있지만 아직 연결된 발신처가 없습니다(2026-09-29 기준 수신 기록 0건). 연결 방법은 `docs/NEXT-STEPS-2026-09-21.md`.

### 출고·자동 수령 확인
- 입금 확인 후 공급자가 사진과 함께 출고 → 7일 뒤 자동 거래 완료(구매자·공급자·운영자 알림).
- 분쟁이 열려 있으면 자동 완료와 입금 기한 취소가 멈춥니다.

### 분쟁·위약금
- 구매자: 단순 변심 취소(입금 전·입금 후 출고 전), 허위매물·불일치(입금 후), 출고 지연(입금 후), 기타.
- 공급자: 기타(구매자 연락 불가 등).
- 주문당 열린 분쟁은 1건. 상대방은 소명과 사진을 남길 수 있습니다.
- 운영자 처리(운영 탭 → 분쟁·위약금):
  - 기각: 거래 계속, 자동 완료·입금 기한 다시 시작.
  - 취소·환불: 입금된 돈 전액 환불(구매자 책임이면 위약금을 빼고 환불). 차순위 승계 없이 유찰로 끝나고 판매자가 다시 경매할 수 있습니다.
  - 부분 환불: 거래 계속, 수수료와 정산액은 환불 뒤 금액으로 다시 계산.
  - 위약금: 구매자 또는 공급자에게 거래대금 10%. 입금된 구매자 위약금은 환불에서 빼서 바로 "납부"로 처리.
- 환불액은 주문별 누적입니다. 운영자가 화면에 보이는 금액을 송금하고 "송금 완료"를 누르면 그 금액만 기록합니다. 그 사이 다른 처리로 금액이 바뀌었으면 거절되어 새로고침을 요구합니다.
- 이미 부분 환불한 금액이 커서 위약금을 환불에서 뺄 수 없으면 위약금 부과가 거절됩니다. 위약금 없이 처리하거나 따로 받습니다.
- 공급자에게는 구매자가 돌려받는 금액을 보여주지 않습니다(위약금이 드러나므로).

### 자전거래 방지
- 판매자와 같은 사업자번호 계정은 그 판매자의 경매에 입찰할 수 없습니다(403).
- 입찰·등록·프로필 저장 때 IP 해시를 기록합니다. 운영 탭 → 부정거래에 판매자와 IP 또는 사업자번호를 공유한 입찰자가 나오고, 운영자가 경매를 중단할 수 있습니다. 같은 사무실·통신사 공유 IP일 수 있어 자동 차단은 하지 않습니다.

## 6. 구현하지 않은 것

- **PG 에스크로**: 돈은 기존처럼 플랫폼 계좌로 받고 운영자가 정산·환불을 송금합니다. PG 계약 후 연결해야 합니다.
- **위약금 자동 징수**: 위약금은 기록과 이용 제한만 합니다. 실제 수납은 운영자가 확인 후 "납부 확인"을 누릅니다.
- **사업자 소유 확인**: 국세청 진위확인(대표자명·개업일 대조, `/v1/validate`)은 프로필에 대표자명·개업일 입력이 필요해 다음 단계로 남겼습니다.
- **배송지 비노출·물류 연동**: 입금 확인 후 두 사업자가 직접 협의하는 기존 방식 그대로입니다.
- **실시간 푸시형 갱신**: 3초 폴링입니다. 웹소켓은 쓰지 않았습니다.
- **증거 사진 접근 제한**: 업로드 이미지는 추측할 수 없는 주소로만 열리지만 로그인 없이도 열립니다(기존 이미지 경로 방식).
